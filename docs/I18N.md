# Sistema de Internacionalización (i18n)

## Resumen

El sistema de internacionalización permite que la plataforma se traduzca a múltiples idiomas. El idioma por defecto es español (`es`), y el primer idioma traducido es inglés (`en`).

## Arquitectura

### Estrategia híbrida JSON + Base de datos

- **JSON files**: Son el formato base/distribuible. Se encuentran en `web/src/locales/{lang}/{namespace}.json`.
- **Base de datos**: Almacena traducciones importadas, editadas y específicas del nodo.
- **API**: Permite editar traducciones desde la plataforma (UI).

### Componentes principales

1. **Frontend i18n**:
   - `web/src/i18n/index.ts` — Configuración de i18next
   - `web/src/i18n/TranslationProvider.tsx` — Provider de React
   - `web/src/i18n/useT.ts` — Hook personalizado
   - `web/src/locales/{lang}/{namespace}.json` — Archivos de traducción

2. **Backend API**:
   - `internal/api/translations.go` — Endpoints CRUD de traducciones
   - `internal/api/errors.go` — Códigos de error estables
   - `internal/federation/translations_federation.go` — Federación de traducciones

3. **Base de datos**:
   - Migraciones 163-168: tablas `languages`, `translations`, `federated_translations`, permisos, configuración

## Cómo añadir un nuevo idioma

### Método 1: Desde la plataforma (recomendado)

1. Ve a **Configuración → Traducciones** (`/app/translations`)
2. En la sección "Gestionar idiomas", completa:
   - **Código**: ej: `pt`, `fr`, `de` (código ISO 639-1)
   - **Nombre**: ej: `Portuguese`, `French`, `German`
   - **Nombre nativo**: ej: `Português`, `Français`, `Deutsch`
3. Haz clic en "Añadir idioma"
4. El idioma aparece en la lista. Selecciona el idioma para ver las traducciones faltantes.
5. Traduce los textos faltantes en el editor.
6. Guarda los cambios.

### Método 2: Importando un archivo

1. Ve a **Configuración → Traducciones**
2. En la sección "Subir archivo", selecciona un archivo JSON de traducción
3. El archivo debe tener el formato:
   ```json
   {
     "namespace": {
       "key": "traducción",
       "another_key": "otra traducción"
     }
   }
   ```
4. El sistema valida e importa el archivo.

### Método 3: Desde otro nodo federado

1. Otro nodo anuncia que tiene una traducción disponible (vía gossip de federación)
2. Recibes una notificación
3. Ve a **Configuración → Traducciones**
4. En la sección "Traducciones de otros nodos", verás la traducción disponible
5. Haz clic en "Descargar" para descargarla e instalarla

## Formato de los archivos JSON

```json
{
  "namespace": {
    "key": "valor traducido",
    "nested": {
      "key": "valor anidado"
    },
    "interpolation": "Hola {{name}}, tienes {{count}} mensajes"
  }
}
```

- Las claves pueden estar anidadas (se separan con puntos al aplanar)
- La interpolación usa `{{variable}}`
- Los valores son strings

## Convences de naming

- **Namespaces**: minúsculas, singular (ej: `transfer`, no `transfers`)
- **Claves**: snake_case (ej: `transfer_button`, no `transferButton`)
- **Errores**: prefijo `error.` (ej: `error.invalid_credentials`)
- **Navegación**: prefijo `nav.` (ej: `nav.dashboard`)

## Permisos y delegación

El sistema de traducciones usa dos permisos:

| Permiso | Descripción |
|---------|-------------|
| `translations.edit` | Editar traducciones existentes |
| `translations.manage` | Gestionar idiomas, subir/descargar archivos, instalar traducciones federadas |

Estos permisos se integran con el sistema de roles y asamblea existente. La asamblea puede delegar la responsabilidad de traducción:
- Por votación
- A la junta directiva
- A una persona específica
- A una persona que puede delegar más traductores

## Códigos de error del backend

El backend usa códigos de error estables en lugar de mensajes literales. El frontend traduce estos códigos usando el namespace `errors`.

Formato de respuesta de error:
```json
{
  "error_code": "error.invalid_credentials",
  "message": "Usuario o contraseña incorrectos"
}
```

El frontend usa `error_code` para traducir si está disponible, y `message` como fallback.

## Federación de traducciones

### Comportamiento

- **NO se instalan automáticamente**: Las traducciones de otros nodos solo se anuncian.
- **Notificación al admin**: Cuando un nodo federado anuncia una traducción, se notifica al admin.
- **Descarga manual**: El admin decide si descargar e instalar.
- **Sin auto-sincronización**: No hay sincronización automática que cambie el nodo sin aprobación.

### Endpoints de federación

| Endpoint | Método | Descripción |
|----------|--------|-------------|
| `/federation/translations/list` | GET | Lista traducciones disponibles para peers |
| `/federation/translations/download/{lang}` | GET | Descarga archivo de traducción |
| `/federation/translations/sync` | POST | Recibe lista de traducciones de un peer (gossip) |

### Flujo de federación

1. Nodo A tiene una traducción de `en` versión `2.0.0`
2. Nodo A anuncia via gossip: `{language_code: "en", version: "2.0.0", file_hash: "..."}`
3. Nodo B recibe la notificación
4. El admin de Nodo B ve la traducción disponible en `/app/translations`
5. El admin decide: ignorar, descargar, o instalar
6. Si instala, la traducción se aplica al nodo B

## Cómo asegurar que nuevas páginas entren al sistema

### Para desarrolladores

1. **Nunca uses strings literales en español**. Usa `useTranslation` y claves de traducción.
2. **Importa el hook**:
   ```tsx
   import { useTranslation } from 'react-i18next'
   ```
3. **Usa el namespace correcto**:
   ```tsx
   const { t } = useTranslation('dashboard')
   ```
4. **Usa claves descriptivas**:
   ```tsx
   <h1>{t('title')}</h1>
   <button>{t('save_button')}</button>
   ```
5. **Añade las claves a los JSON**:
   - `web/src/locales/es/{namespace}.json`
   - `web/src/locales/en/{namespace}.json`
6. **Para interpolación**:
   ```tsx
   <p>{t('welcome', { name: userName })}</p>
   ```
   JSON: `"welcome": "Hola {{name}}"`

### Detección de traducciones faltantes

El sistema detecta automáticamente las claves que faltan traducir. El admin puede verlas en:
- `/app/translations` → "Traducciones faltantes"

## Alcance

### Incluido

- Sitio web principal (frontend + backend)
- Setup wizard (instalación multilingüe)
- Mensajes de error del backend
- Sitio público (títulos y subtítulos de páginas template)
- Federación de traducciones entre nodos

### No incluido (futuro)

- POS Android (`punto-de-venta-pos/`) — tendrá su propio módulo de traducción
- POS Web separado — tendrá su propio módulo de traducción
- Traducción automática (machine translation)
- Instalación automática de traducciones desde federación

## Configuración del setup

El setup wizard comienza con la selección de idioma (paso 0), antes de cualquier otra configuración. El idioma seleccionado se envía al backend como `default_language` en `/setup/init` y se persiste como idioma por defecto del nodo.
