fix: Eliminar todos los localhost hardcoded - dominio dinamico

PROBLEMA: 80 instancias de localhost hardcoded en el codigo Go.
Cuando un nodo tiene un dominio diferente, el codigo usaba localhost
como fallback y no encontraba los datos.

SOLUCION: Funcion db.ResolveNodeDomain() que SIEMPRE lee el dominio
real desde node_config. Nunca usa localhost como fallback.

Orden de resolucion:
1. Header X-Node-Domain (del frontend)
2. Tabla node_config (dominio real guardado al instalar)
3. config.yaml (dominio del archivo de configuracion)
4. Vacio (el caller maneja el caso)

CAMBIOS:
- Nueva funcion db.ResolveNodeDomain() en internal/db/connection.go
- Nueva funcion db.MigrateDomainData() para migrar datos si cambia
  el dominio (actualiza 33 tablas con columna node_domain)
- 76 reemplazos en 7 archivos (system, assembly, scoped_assembly,
  notifications, tax, recovery, external)
- 3 INSERTs con localhost hardcoded corregidos (creacion de
  sesiones de asamblea automaticas)
- Agregado campo nodeDomain a AssemblyHandler, TaxHandler,
  ScopedAssemblyHandler, NotificationHandler
- RecoveryHandler ahora recibe Pool para poder resolver dominio
- routes.go pasa nodeDomain a todos los handlers

PRINCIPIO: El dominio es una variable dinamica que se lee de
node_config. Si el dominio cambia, la variable automaticamente
devuelve el nuevo valor. No hay nada hardcoded.
