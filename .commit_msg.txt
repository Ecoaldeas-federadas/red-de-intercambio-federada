fix: Proxy reverso con Docker networking + demo sin bucle + help text

PROBLEMAS:
1. localhost:9091 no funciona dentro de Docker (cada contenedor tiene
   su propio localhost). El proxy no podia alcanzar el demo ni los
   servicios instalados.
2. El nodo demo es un clon del nodo principal, asi que tambien tenia
   el middleware de proxy -> bucle infinito.
3. La URL /demo/demo era confusa.
4. El help text del dominio no tenia ejemplos claros.

SOLUCIONES:

1. Docker networking:
   - Demo: usa nombre del contenedor "demo-app:9091" (misma red
     de docker-compose, no necesita localhost)
   - Servicios instalados (POS, etc.): usa "host.docker.internal:<port>"
     para alcanzar puertos expuestos en el host
   - Agregado extra_hosts: host.docker.internal:host-gateway
     en docker-compose.yml para compatibilidad con Linux

2. Demo sin bucle:
   - El proxy middleware solo se activa cuando basePath == "" (nodo
     principal). El nodo demo (basePath="/demo") no tiene proxy.
   - Cuando basePath esta seteado, se agrega un middleware que strip
     basePath de las llamadas API: /demo/api/users -> /api/users
     Esto permite que el demo reciba llamadas API via el proxy del
     padre sin cambiar como se registran las rutas API.

3. Demo: proxy NO strip del prefix:
   - /demo -> demo-app:9091/demo (path completo, no strip)
   - El demo tiene basePath="/demo" y maneja /demo/ -> frontend
   - /demo/api/... -> demo-app:9091/demo/api/... -> strip /demo -> /api/...
   - URL final: https://dominio/demo (no /demo/demo)

4. api.ts: API_BASE usa __BASE_PATH__:
   - Nodo principal: API_BASE = "/api"
   - Nodo demo: API_BASE = "/demo/api"
   - Asi el frontend del demo llama a /demo/api/... que el proxy
     del padre redirige al demo, y el demo strip /demo -> /api/...

5. Help text del dominio:
   - Placeholder mas claro: "mi-aldea.org"
   - Ejemplos debajo del campo con formato code
   - Indica sin https://, sin www., sin puerto
