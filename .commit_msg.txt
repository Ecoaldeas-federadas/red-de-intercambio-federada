fix: actualizacion del nodo sobrevive recarga de pagina + boton cancelar

PROBLEMAS:
1. Al recargar la pagina, la consola de actualizacion desaparecia
   porque el estado solo vivia en React state, no se consultaba al backend
2. No habia boton para cancelar una actualizacion atascada
3. El backend no escribia estado inicial antes de delegar al
   updater-controller, asi que si el controller no respondia, el
   estado quedaba vacio y el frontend mostraba "Esperando..." para siempre
4. No habia logging de errores de conexion al updater-controller
5. Si el updater-controller no recibia la instruccion, no habia forma
   de saber por que

SOLUCION:

1. Backend update_handler.go:
   - Nuevo writeUpdateState(): escribe estado a /update-state/update.json
     ANTES de delegar al updater-controller
   - Nuevo appendUpdateLog(): agrega lineas al log compartido
   - updateNode() ahora:
     * Verifica si ya hay update en curso (409 si ya hay)
     * Escribe estado "running" inicial antes de cualquier cosa
     * Loggea cada intento de conexion al updater-controller
     * Loggea errores de rebuild del controller
   - Nuevo endpoint POST /api/node/cancel-update:
     * Ecribe estado "cancelled" al archivo de estado
     * Mata contenedores desechables fmc-updater-*
   - Nuevo handler cancelUpdate()

2. do_update.sh:
   - Nuevo check_cancelled(): verifica si el estado es "cancelled"
     antes de cada paso y se detiene si fue cancelado
   - Verificaciones de cancelacion antes de:
     * git fetch
     * git reset
     * docker build node-app
     * docker up node-app (reiniciar)

3. Frontend NodeSettings.tsx NodeUpdateSection:
   - Al cargar (useEffect), consulta /node/update-status
   - Si el estado es "running", restaura la consola automaticamente
     y reinicia el polling
   - Esto significa que al recargar la pagina, la consola vuelve a aparecer
   - Nuevo boton "Cancelar actualizacion" (rojo, con icono X)
   - El boton llama a POST /node/cancel-update
   - Desaparece cuando el estado es completed/error/cancelled
   - Detecta estado "cancelled" y detiene el polling
   - Refactor: startPolling() extraido como funcion reutilizable
     (usado tanto por updateNode como por la restauracion al cargar)
