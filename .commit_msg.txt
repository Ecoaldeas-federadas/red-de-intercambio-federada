feat: descubrimiento de nodos por gossip (chisme) + solicitudes de federacion

Implementa el protocolo gossip para que los nodos se descubran entre si
sin necesidad de un servidor central. Ademas permite enviar solicitudes
de federacion a nodos descubiertos.

=== Como funciona el descubrimiento ===

1. Cada nodo mantiene una lista de nodos conocidos (federation_known_nodes)
2. Periodicamente, cada nodo comparte su lista con sus peers directos
3. Los peers reciben la lista y agregan los nodos nuevos como descubiertos
4. Asi, basta con que un nodo se feder con uno solo para que toda la red
   descubra que existe (efecto chisme/cadena)
5. Periodicamente, cada nodo verifica si los nodos descubiertos estan activos
6. Si un nodo no responde despues de varios intentos, se marca como inactivo
7. Periodicamente, la lista de inactivos se limpia (configurable por nodo)

=== Backend (internal/api/node_discovery.go) ===

Endpoints publicos (sin auth, para que otros nodos los consulten):
- GET  /api/public/node-info: perfil publico del nodo
- POST /api/public/federation-request: recibir solicitud de federacion
- POST /api/public/known-nodes-sync: recibir lista de nodos de otro nodo

Endpoints privados (requieren auth + federation.change_config):
- GET  /api/nodes/discovered: listar nodos descubiertos
- GET  /api/nodes/federated: listar peers directos
- GET  /api/nodes/inactive: listar nodos inactivos
- GET  /api/nodes/discovery-config: obtener config de descubrimiento
- PUT  /api/nodes/discovery-config: actualizar config
- POST /api/nodes/federation-request: enviar solicitud a otro nodo
- GET  /api/nodes/federation-requests: listar solicitudes
- POST /api/nodes/federation-requests/{id}/respond: responder solicitud
- POST /api/nodes/discovered/{domain}/check: verificar salud de un nodo
- POST /api/nodes/discovered/sync-now: forzar sincronizacion gossip
- DELETE /api/nodes/discovered/{domain}: eliminar nodo descubierto
