fix: signature verification failed + RP ID dinamico para WebAuthn

PROBLEMA 1: "signature verification failed (ES256)"
El codigo usaba clientDataJSON raw en verifyData, pero el spec WebAuthn
requiere SHA256(clientDataJSON). Los datos firmados son:
  authenticatorData || SHA256(clientDataJSON)
no:
  authenticatorData || clientDataJSON

Fix: calcular sha256.Sum256(clientDataBytes) y concatenar ese hash
con authDataBytes. Esto aplica tanto a Ed25519 como a ES256.

Tambien se anade fixECDSASignatureFormat() como fallback: algunos
autenticadores producen firmas ES256 en formato raw (r||s, 64 bytes)
en vez de ASN.1 DER. Si VerifyASN1 falla, se intenta convertir.

PROBLEMA 2: No se puede registrar passkey desde el dominio
El PasskeyManager se inicializaba con cfg.Node.Domain ("nodo-a.org")
como RP ID fijo y cors_origins: ["http://localhost:3000"]. Pero
WebAuthn requiere que el RP ID coincida con el dominio desde el que
se accede (localhost, feria.loanstly.com, etc.).

Fix: RP ID y origin ahora son dinamicos, derivados del request:
- deriveRPID(r): extrae el dominio del header Origin o Host
- deriveOrigin(r): construye la URL de origen del request
- BeginRegistration y BeginLogin ahora aceptan rpID como parametro
- VerifyRegistration acepta cualquier origen que:
  1. Este en la lista configurada, O
  2. Coincida con el origin del request, O
  3. Sea localhost/127.0.0.1 (desarrollo)

Esto permite que WebAuthn funcione correctamente desde cualquier
dominio (localhost, feria.loanstly.com, etc.) sin cambiar la config.
