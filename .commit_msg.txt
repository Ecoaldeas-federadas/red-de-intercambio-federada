PROBLEMA 1: Windows confirma el registro pero el passkey no aparece

Causa raiz: el passkeyAdapter.VerifyRegistration en cmd/node/main.go
hacia un type assertion directo:
  resp, ok := response.(crypto.RegistrationResponse)
Pero cuando el JSON del frontend se deserializa en interface{},
se convierte en map[string]interface{}, NO en crypto.RegistrationResponse.
El type assertion SIEMPRE fallaba con "invalid registration response
type", asi que el passkey nunca se guardaba en la base de datos.

Fix: el adapter ahora maneja ambos casos:
- crypto.RegistrationResponse: lo usa directo
- map[string]interface{}: re-marshall a JSON y re-unmarshal al tipo
  correcto antes de llamar a VerifyRegistration
Lo mismo se aplico a VerifyLogin para el flujo de login con passkey.

PROBLEMA 2: prompt() abre alerta nativa de Windows

El navegador usa prompt() de JavaScript que abre un dialogo nativo
del SO en vez de un modal dentro de la app.

Fix: reemplazado prompt() por un modal interno en Profile.tsx:
- Estado showPasskeyModal y passkeyLabel
- Modal con input de texto, boton Cancelar y Continuar
- Enter en el input registra el passkey
- Click fuera del modal lo cierra
