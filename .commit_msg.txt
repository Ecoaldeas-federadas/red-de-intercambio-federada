fix: consola de actualizacion persistente que sobrevive reinicio del nodo

PROBLEMA:
La consola de estado de actualizacion desaparecia despues de 1 segundo
porque:
1. El polling a /node/update-status fallaba cuando node-app se reiniciaba
2. El catch era vacio - no mostraba nada al usuario
3. El estado solo se mostraba si era running/error/completed, no idle
4. El usuario se quedaba viendo "Actualizando..." sin saber que pasaba
5. No habia feedback visual de que se estaba esperando reconexion

SOLUCION:
Rediseñado NodeUpdateSection con consola de estado persistente:

1. Consola estilo terminal siempre visible durante updating:
   - Fondo negro, texto monoespaciado
   - Muestra el log en tiempo real del updater-controller
   - Se actualiza cada 2s (antes era 3s)

2. Polling resiliente que NO para cuando el nodo se reinicia:
   - Antes: catch vacio, seguia sin mostrar nada
   - Ahora: cuenta fallos consecutivos, muestra "Nodo reiniciandose"
   - Sigue reintentando hasta que el nodo vuelve
   - Muestra numero de intento de reconexion

3. Estados visuales claros:
   - idle: "Esperando inicio de actualizacion..."
   - running: mensaje del updater + log + barra progreso 50%
   - nodeRestarting: "Nodo reiniciandose... esperando reconexion"
     + barra progreso 70% + mensaje explicativo
   - completed: "Nodo actualizado correctamente" + barra 100%
   - error: mensaje de error + barra roja

4. Barra de progreso visual que cambia segun el estado:
   - Azul pulsante: actualizando
   - Amber: nodo reiniciandose
   - Verde: completado
   - Rojo: error

5. Mensaje explicativo durante reinicio:
   "El nodo se esta reiniciando. Esto es normal durante la actualizacion.
    El updater-controller sigue trabajando en segundo plano.
    Reintentando conexion... (intento N)"
