feat: federacion de productos entre nodos con aprobacion individual

Cuando un nodo crea un producto nuevo, lo comunica a los demas nodos
federados. Cada nodo debe aprobarlo individualmente para que este
disponible en su territorio. Si no se aprueba, no se puede usar para
producir, comprar ni nada.

CAMBIOS:

1. MIGRACION 043: Tabla product_federation_proposals
   - Registra productos propuestos por otros nodos
   - Campos: source_node, source_product_id, name, category, unit,
     price_per_unit, is_composite, composition, status
   - status: pending, approved, rejected
   - Campos nuevos en products: source_node, source_product_id

2. PROTOCOLO DE FEDERACION: Mensaje ProductProposal
   - Nuevo tipo de mensaje en protocol.go
   - ProductProposalPayload con todos los datos del producto
   - Handler handleProductProposalMessage en server.go
     * Recibe propuesta via /federation/inbox
     * Guarda en product_federation_proposals como 'pending'
     * ON CONFLICT evita duplicados
   - Funcion BroadcastProductProposal
     * Lista nodos federados conocidos
     * Envia propuesta a cada uno

3. API: Endpoints para gestionar propuestas federadas
   - GET /api/federation/products/pending: listar pendientes
   - GET /api/federation/products/all: listar todas (historico)
   - POST /api/federation/products/{id}/approve: aprobar
     * Inserta producto en catalogo local como aprobado
     * Marca origen como 'federated' con source_node
   - POST /api/federation/products/{id}/reject: rechazar
     * Marca como rejected con notas

4. FRONTEND: Products.tsx con panel de productos federados
   - Boton "Federados" con contador de pendientes
   - Panel que muestra productos propuestos por otros nodos
   * Nombre, nodo origen, precio, categoria
   * Descripcion y composicion si es compuesto
   - Botones Aprobar / Rechazar (requiere permiso products.manage)

MODELO:

- Nodo A crea producto nuevo -> BroadcastProductProposal
- Nodo B, C, D reciben propuesta -> guardan como 'pending'
- Nodo B aprueba -> producto disponible en Nodo B
- Nodo C rechaza -> producto no disponible en Nodo C
- Nodo D ignora -> producto sigue pendiente en Nodo D
- Productos aprobados se pueden usar para:
  * Comprar en tienda
  * Como componente de productos compuestos
  * Como materia prima
- Productos no aprobados no se pueden usar para nada
