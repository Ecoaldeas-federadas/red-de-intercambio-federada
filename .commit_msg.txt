fix: login deriva node_domain de node_config, no de config.yaml

El fix anterior (buscar sin filtrar por dominio) rompia la federacion:
si hay dos nodos cada uno con su admin, el login encontraria el
primero que encuentre.

Fix correcto: el node_domain se determina en este orden:
1. Header X-Node-Domain (enviado por el frontend, viene de /api/config)
2. Tabla node_config (dominio real guardado al crear el nodo)
3. ah.NodeDomain (del config.yaml, puede estar vacio)

Asi el login SIEMPRE filtra por node_domain, pero obtiene el dominio
correcto desde la BD (node_config) si el config.yaml esta vacio o si
el frontend no envia el header.

Aplicado a:
- passwordLogin: busca usuario por username + node_domain
- beginLogin (passkey): busca usuario por username + node_domain
