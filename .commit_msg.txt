Correcciones al flujo del POS web:

1. FLUJO DE REGISTRO CORRECTO (como terminales fisicos)
   - El usuario abre el POS en su dispositivo
   - El POS genera: terminal_id, claves Ed25519, huella del dispositivo
   - El POS MUESTRA todos los datos (texto + QR) para que el usuario
     se los dé al administrador encargado
   - El administrador entra a la plataforma y registra el terminal
     (POST /api/nfc/terminal/register - requiere permiso nfc.register_terminal)
   - El administrador le da al usuario el registration_token
   - El usuario ingresa el registration_token en el POS
   - El POS completa el registro y se autentica
   - Los usuarios NO pueden registrar terminales directamente

2. BLOQUEO / DESBLOQUEO LOCAL
   - El usuario puede bloquear el terminal desde el POS con un codigo
   - Solo con el codigo puede desbloquearlo
   - El administrador tambien puede bloquear/desbloquear desde la plataforma
   - Backend: POST /api/nfc/terminal/{id}/block y /unblock
   - El codigo se guarda como hash bcrypt (nunca plaintext)

3. DOCKER SEPARADO PARA EL POS
   - docker/Dockerfile.pos: build Vite + serve con nginx
   - docker-compose.yml: servicio pos-web en puerto 3001
   - El POS se sirve como static files (100% frontend)
   - Se comunica con el nodo via API (no necesita backend propio)
   - PWA instalable desde el navegador
