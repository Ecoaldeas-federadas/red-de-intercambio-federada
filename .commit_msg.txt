fix: Datos locales con variable __LOCAL__ - dominio dinamico real

PROBLEMA: Los datos se guardaban con el nombre literal del dominio.
Si cambiabas el dominio del nodo, habia que migrar todos los datos.

SOLUCION: Los datos locales se guardan con la constante __LOCAL__
(LOCAL_NODE_DOMAIN), no con el nombre real del dominio.

COMO FUNCIONA:
- db.LOCAL_NODE_DOMAIN = "__LOCAL__" (constante fija)
- db.ResolveNodeDomain() devuelve "__LOCAL__" para datos locales
- db.ActualNodeDomain() devuelve el dominio real (para federacion)
- El dominio real solo se guarda en node_config (una fila)
- Si cambias el dominio, cero migracion: los datos siguen en __LOCAL__

MIGRACION UNA SOLA VEZ:
- db.MigrateDomainData() convierte todos los datos legacy
  (dominio real, localhost, default) a __LOCAL__
- Se ejecuta automaticamente al iniciar el nodo
- No toca node_config (que guarda el dominio real)
- No toca tablas de nodos remotos (node_federation_keys, etc.)

CAMBIOS:
- connection.go: LOCAL_NODE_DOMAIN, ResolveNodeDomain, ActualNodeDomain,
  MigrateDomainData reescritos
- cmd/node/main.go: ejecuta MigrateDomainData al iniciar, usa
  LOCAL_NODE_DOMAIN para seeds
- setup.go: crea usuarios y datos locales con LOCAL_NODE_DOMAIN,
  guarda dominio real solo en node_config
- auth.go: resolveNodeDomain usa ResolveNodeDomain para login,
  token JWT usa ActualNodeDomain para federacion

PRINCIPIO: El dominio es una variable. Los datos locales se guardan
con un valor fijo (__LOCAL__). El dominio real solo se usa para
federacion y URLs. Si cambias el dominio, no hay que migrar nada.
