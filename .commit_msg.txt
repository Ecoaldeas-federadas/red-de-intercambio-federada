fix: verificacion de actualizaciones no detectaba commits nuevos

PROBLEMA:
El boton "Verificar actualizaciones" siempre decia "El nodo esta
actualizado" incluso cuando habia commits nuevos en el repo.
El usuario hizo git pull manual y descargo commits 9793a07..a5d38d8
que la verificacion no habia detectado.

CAUSA:
`git fetch origin main` actualiza FETCH_HEAD pero en algunas
configuraciones de git NO actualiza refs/remotes/origin/main.
Entonces `git log HEAD..origin/main` comparaba contra el ref viejo
y no encontraba nada nuevo.

SOLUCION:

1. Backend checkUpdates():
   - Cambio: `git fetch origin main` -> `git fetch origin --prune`
     (fetch completo que actualiza TODOS los refs, no solo main)
   - Fallback: si origin/main no encuentra commits nuevos, probar
     con FETCH_HEAD como comparacion
   - Nuevo: obtener commit remoto (origin/main) para mostrarlo
   - Nuevo: enmascarar token en remote URL para debug
   - Nuevo: incluir remote_url y fetch_output en la respuesta

2. Frontend NodeSettings.tsx:
   - Mostrar "Commit remoto" ademas de "Commit actual"
     (si son diferentes, hay actualizacion)
   - Mostrar remote URL y fetch output como info de debug
   - Solo mostrar "El nodo esta actualizado" si NO hay error

Resultado: Ahora la verificacion hace fetch completo de todos los
refs y compara contra origin/main actualizado. Si por alguna razon
origin/main no se actualiza, usa FETCH_HEAD como fallback.
