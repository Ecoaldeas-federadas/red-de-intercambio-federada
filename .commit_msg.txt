fix: login passkey 500 - panic y solo soportaba Ed25519, no ES256

El login con passkey daba 500 Internal Server Error por dos causas:

PROBLEMA 1: Panic en parseCOSEPublicKey (causa del 500)
La linea kty.(int) hacia un type assertion directo que puede panic
si CBOR decodifica el valor como uint64 en vez de int. El middleware
Recoverer captura el panic y devuelve 500.

Fix: nueva funcion toInt() que usa type switch para convertir
de forma segura int, int64, uint64, uint, float64 a int.

PROBLEMA 2: Solo soportaba Ed25519, pero Windows usa ES256
PubKeyCredParams ofrece algoritmos -7 (ES256) y -257 (RS256).
Windows Hello crea llaves ES256 (ECDSA P-256, kty=2), pero
parseCOSEPublicKey solo soportaba Ed25519 (kty=8) y ed25519.Verify
no puede verificar firmas ECDSA.

Fix: reescrito el soporte criptografico para manejar ambos:
- detectCOSEKeyType: detecta si la clave es Ed25519 (kty=8) o ES256 (kty=2)
- parseEd25519PublicKey: parsea claves Ed25519 desde COSE
- parseES256PublicKey: parsea claves ECDSA P-256 desde COSE
  (extrae coordenadas x, y y reconstruye ecdsa.PublicKey)
- VerifyLogin: usa ed25519.Verify para Ed25519 o ecdsa.VerifyASN1
  con SHA-256 para ES256

Esto permite que Windows Hello, FaceID, TouchID y la mayoria de
autenticadores funcionen (todos usan ES256 por defecto).
