feat: monitoreo de cluster YugabyteDB + alerta de nodos necesarios

El sistema ahora monitorea automaticamente el cluster YugabyteDB y
avisa cuando se necesita agregar un nuevo nodo.

Configuracion (config.yaml):
- cluster.min_nodes: minimo de nodos requeridos (default: 2)
- cluster.tablet_limit_per_node: limite por nodo (default: 534)
- cluster.alert_threshold: % de uso para alertar (default: 80)
- cluster.nodes: lista de nodos del cluster

Backend (cluster_handler.go):
- GET /api/cluster/status: estado del cluster
  - Nodos activos vs configurados vs minimos
  - Tabletas usadas vs limite total
  - Porcentaje de uso
  - Nodos necesarios
  - Nivel de alerta (ok, warning, critical)
- POST /api/cluster/check: verifica y envia notificacion
  - Notifica a administradores cuando se necesita un nodo
- Calcula nodos necesarios basado en uso de tabletas
- Consulta yb_tablet_meta y yb_cluster_info de YugabyteDB
- Fallback: estima tabletas contando tablas e indices

Frontend (NodeSettings.tsx, tab "Base de Datos"):
- Panel de estado del cluster al inicio del tab
- Metricas: nodos activos, tabletas, % uso, nodos necesarios
- Barra de progreso de capacidad (verde/amarillo/rojo)
- Boton "Verificar" para forzar verificacion
- Instrucciones para agregar nodos cuando es necesario
- Diferencia entre mismo servidor (desarrollo) y separado (produccion)

Alertas:
- ok: uso < 80%
- warning: uso >= 80% (considerar agregar nodo)
- critical: uso >= 90% o nodos < minimo (agregar urgentemente)
