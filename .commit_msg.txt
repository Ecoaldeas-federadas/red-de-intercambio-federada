fix: servicios federados no cargaban (res.data undefined)

Bug: la pagina /app/services mostraba "No se encontraron servicios" y
el error en consola era:
  TypeError: Cannot read properties of undefined (reading 'services')

Causa: el frontend usaba `res.data.services` pero api.get() devuelve
directamente el JSON parseado (no hay .data). El backend devuelve
{"services": [...]}, asi que deberia ser `res.services`.

Lo mismo pasaba con todas las llamadas de VoIP (res.data.message,
res.data.gateways, res.data.extensions, etc.) y los catch blocks
que usaban e.response?.data?.error (axios-style) cuando el wrapper
apiFetch lanza new Error(err.error) que se captura como e.message.

Arreglado en FederatedServices.tsx:
- loadServices: res.data.services -> res?.services
- installService: res.data.success -> res.success
- downloadService: res.data.docker_compose -> res.docker_compose
- loadPSTNGateways: res.data.gateways -> res?.gateways
- loadBalance: res.data -> res
- loadCDR: res.data.calls -> res?.calls
- autoConfigureRoutes: res.data.message -> res.message
- createPSTNGateway: res.data.message -> res.message
- rechargeVoIP: res.data.message -> res.message
- loadConfig: res.data -> res
- loadExtensions: res.data.extensions -> res?.extensions
- loadRoutes: res.data.routes -> res?.routes
- generateCode: res.data.message -> res.message
- createExt: res.data.message -> res.message
- createRoute: res.data.message -> res.message
- Todos los catch: e.response?.data?.error -> e.message

Ahora los 20+ servicios del catalogo deberian cargar correctamente.
