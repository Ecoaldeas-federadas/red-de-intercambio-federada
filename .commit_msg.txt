feat: modelo criptografico completo para tarjetas NFC (AES-128 + challenge-response)

Las tarjetas NFC ya no son "tontas" (solo UID clonable). Ahora tienen
claves AES-128 embebidas que prueban criptograficamente que son legitimas.

MODELO CRIPTOGRAFICO:

1. PROVISIONAMIENTO (migracion 118 + card_crypto.go)
   - Servidor genera clave AES-128 unica por tarjeta
   - Clave se escribe en la tarjeta (DESFire EV3 o NTAG424)
   - Clave se guarda cifrada en la BD (cifrada con clave maestra del nodo)
   - Tabla nfc_card_keys extendida con aes_key_encrypted, key_version,
     sun_counter, auth_fail_count, crypto_blocked_until
   - Endpoint: POST /api/nfc/cards/provision-crypto

2. DISTRIBUCION DE CLAVES A TERMINALES/APPS
   - Terminal/app autenticada pide la clave AES de una tarjeta
   - Clave se entrega sobre canal cifrado (Ed25519 + AES-256-GCM)
   - Terminal descifra en memoria, NUNCA en disco
   - Sesion de distribucion registrada para auditoria
   - Tabla card_key_sessions
   - Endpoint: POST /api/nfc/cards/{uid}/request-key

3. CHALLENGE-RESPONSE (DESFire EV3)
   - Servidor genera challenge (nonce aleatorio de 16 bytes)
   - Terminal envia challenge a la tarjeta
   - Tarjeta responde con AES(challenge, key)
   - Servidor verifica la respuesta
   - Anti-replay: challenge se marca como usado
   - Tabla nfc_card_challenges con expiracion de 60s
   - Endpoints: POST /challenge, POST /verify-response

4. NTAG424 SUN (Secure Unique Number)
   - NTAG424 genera MAC(AES, UID|counter) en cada tap
   - Servidor verifica el MAC con la misma clave AES
   - Counter anti-replay: cada tap incrementa el counter
   - Si counter <= almacenado = replay attack detectado
   - Endpoint: POST /api/nfc/cards/{uid}/verify-sun

5. SEGURIDAD
   - 5 fallos de auth = tarjeta bloqueada 30 minutos
   - Clave maestra del nodo cifrada con NODE_MASTER_KEY (env var)
   - Tabla node_master_keys para rotacion de clave maestra
   - Rotacion de claves por tarjeta: POST /rotate-key
   - Bloqueo de tarjeta: POST /block-crypto
   - Estado criptografico: GET /crypto-status

FLUJO PARA APP ANDROID + LECTOR BLUETOOTH:
1. App se autentica con el servidor (Ed25519 mutual auth)
2. App lee UID de la tarjeta via lector Bluetooth
3. App pide clave AES al servidor (canal cifrado)
4. App descifra clave en memoria
5. App envia challenge a la tarjeta via Bluetooth
6. Tarjeta responde con AES(challenge, key)
7. App envia respuesta al servidor
8. Servidor verifica y procesa el pago
9. App borra la clave de memoria

Frontend: Tab "Tarjetas Crypto" en NodeSettings con:
- Provisionamiento de nuevas tarjetas
- Muestra clave AES para escribir en la tarjeta
- Consulta de estado criptografico
- Bloqueo de tarjetas
