fix: CRLF en scripts shell rompe updater-controller dentro de Docker

PROBLEMA:
El updater-controller fallaba con:
  socat E execvp("/updater-controller.sh"): No such file or directory

Causa: git autocrlf=true en Windows convierte LF a CRLF en los scripts .sh.
Cuando Docker COPY los mete al contenedor Linux, el shebang #!/bin/sh\r
no encuentra el interprete /bin/sh\r (con \r al final) y falla.

Esto pasa especialmente despues de git reset --hard origin/main dentro
de do_update.sh, que re-checkoutea los archivos con CRLF.

SOLUCION (3 niveles):

1. .gitattributes (nuevo):
   *.sh text eol=lf  -> fuerza LF en scripts shell
   *.ps1 text eol=crlf -> mantiene CRLF en PowerShell

2. Dockerfile.updater-controller:
   Agregado: RUN sed -i 's/\r$//' /updater-controller.sh /do_update.sh
   despues de COPY. Esto strip CRLF si git los introdujo.
   Tambien agregado ls -la para debug.

3. do_update.sh:
   Auto-fix al inicio: si detecta \r en si mismo, hace sed y re-exec.
   Esto maneja el caso donde git reset --hard re-checkoutea con CRLF
   y do_update.sh ya esta corriendo.

4. update_handler.go (contenedor desechable):
   Agregado sed -i antes de ejecutar do_update.sh en el contenedor
   alpine desechable, por si los scripts montados tienen CRLF.
