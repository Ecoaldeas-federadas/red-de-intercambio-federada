fix: Proxy reverso dinamico para todos los servicios + demo

PROBLEMA: Cada servicio instalado (POS, PeerTube, Mastodon, etc.) y el
nodo demo usaban puertos directos (:3001, :9091, etc.). Esto no funciona
cuando el dominio base ya usa un puerto (8080) y requiere que el usuario
recuerde puertos.

SOLUCION: Proxy reverso dinamico en el backend que redirige
/<service_id> -> http://localhost:<port> para cada servicio instalado.

COMO FUNCIONA:
- Middleware en chi intercepta todos los requests
- Si el primer segmento del path es un servicio instalado (en installed_services),
  redirige al puerto interno de ese servicio
- /pos -> localhost:3001 (POS Web)
- /demo -> localhost:9091 (nodo demo)
- /peertube -> localhost:9006 (PeerTube)
- /mastodon -> localhost:3000 (Mastodon)
- etc.
- Las rutas /api/*, /uploads/*, /images/* no se interceptan
- Si el primer segmento no es un servicio, pasa al frontend normal

FRONTEND:
- buildServiceURL ahora usa /<service_id> en lugar de :<port>
- Cada tarjeta de servicio instalado muestra la URL de acceso
- Boton "Abrir" visible cuando el servicio esta corriendo
- URLs del demo cambiadas de localhost:9091 a /demo

VENTAJAS:
- El usuario no necesita recordar puertos
- Todo funciona bajo el mismo dominio
- No hay conflicto de puertos
- El dominio base (8080) redirige al nodo
- /pos, /demo, /peertube, etc. redirigen a cada servicio
