fix: Detectar nombre del proyecto docker compose correctamente

PROBLEMA RAIZ:
El update handler corre dentro del contenedor y usa /project como
directorio. Docker compose genera nombres de contenedor basados en
el directorio: "project-node-app-1", "project-yugabytedb-1".

Pero el deployment real usa "red-de-intercambio-federada-node-app-1"
porque se desplego desde C:\Users\usuario\Downloads\red-de-intercambio-federada\.

Al hacer docker compose up, se creaban contenedores "project-*" que
chocaban con los "red-de-intercambio-federada-*" existentes por los
puertos (5433, 8080, etc).

SOLUCION:
Ahora el update handler y startDemoNode detectan el nombre del
proyecto actual leyendo el label "com.docker.compose.project" del
contenedor en el que estan corriendo. Usan ese nombre con
--project-name en todos los comandos docker compose.

Asi, docker compose up recrea el contenedor correcto
(red-de-intercambio-federada-node-app-1) en vez de crear uno nuevo
(project-node-app-1).
