fix: login con passkey no funcionaba - backend y frontend eran stubs

El login con passkey era completamente no funcional. Tanto el backend
como el frontend eran stubs que no implementaban WebAuthn real.

PROBLEMA 1: Backend beginLogin (500 Internal Server Error)
- Pasaba nil como credential IDs (no buscaba los passkeys del usuario)
- Type assertion options.(map[string]interface{})["challenge"] fallaba
  porque BeginLogin retorna *crypto.LoginChallenge, no map
- Almacenaba uuid.Nil como user_id en el challenge store

Fix beginLogin:
- Busca el usuario por username + node_domain en la BD
- Obtiene los credential_id de user_passkeys del usuario
- Pasa los credential IDs reales a BeginLogin
- Extrae el challenge con type assertion correcto (*LoginChallenge)
- Almacena el user_id real en el challenge store

PROBLEMA 2: Backend finishLogin era un stub peligroso
- No verificaba la firma criptografica
- Generaba un token con uuid.New() (usuario aleatorio!)
- Aceptaba cualquier response vacio

Fix finishLogin:
- Recupera el user_id del challenge store
- Busca el passkey del usuario por credential_id en la BD
- Verifica la firma con PasskeyManager.VerifyLogin
- Actualiza sign_count y last_used_at
- Genera el token con el user_id y username correctos

PROBLEMA 3: Frontend handlePasskeyLogin no usaba WebAuthn
- Enviaba session_key: 'temp' y response: {}
- No llamaba navigator.credentials.get()

Fix frontend:
- Llama a /auth/login/begin para obtener opciones
- Usa navigator.credentials.get() con las opciones reales
- Envia la respuesta WebAuthn real (authenticatorData, signature,
  clientDataJSON) al backend para verificacion
